# ADR-013: The `/docs` surface — machine-readable API documentation

## Status

Accepted

## Context

The gateway's HTTP surface was specified in prose only: [client-gateway.md](../contracts/client-gateway.md) and [gateway-management.md](../contracts/gateway-management.md) are authoritative for maintainers and coding agents, but nothing about the surface was machine-readable. An OpenAI-SDK integrator can codegen against the standard `/llm/v1` protocol shapes, yet the gateway's management surface is custom — its routes, masking rule, discovery reports, and auth actions existed in no consumable description, and a human reader had no browsable reference short of reading the specs. The namespace scheme ([ADR-005](./005-gateway-surface-namespace.md)) fixed three surfaces — LLM `/llm/v1`, management `/api`, SPA `/ui` — and that ADR is immutable now that it is committed: extending the namespace set is a new decision referencing it, not an edit.

Two building blocks settled the mechanism: `hono-openapi` derives an OpenAPI document from `describeRoute` configs attached to a Hono route table, and `zod` describes wire shapes as data. The open questions were architectural, not mechanical: where the description lives (handwritten artifact vs generated from the route table), whether describing a request means validating it at runtime, whether a documentation URL needs a gate, and where the documentation UI's assets come from.

The ADR bar is met: the decision is cross-cutting (both HTTP contracts, a new namespace, two build-time dependencies), effectively irreversible once external consumers generate SDKs against the published document, and each sub-decision had a real alternative rejected for cause.

## Decision

1. **A fourth namespace: `/docs`, documentation-only.** `GET /docs/openapi.json` serves the OpenAPI 3.1 document generated at BUILD time: `bun run apidocs` (`src/httpapi/generate-openapi.ts`) compiles it with hono-openapi's `generateSpecs` from the `OPENAPI_ROUTES` table — stub routes carrying the `describeRoute` configs, no handler ever executes — and writes `dist/openapi.json`; the mount serves that artifact statically, reading it per request exactly like the SPA index.html, and a missing (or corrupt) artifact answers the envelope 404 with the regenerate hint — the server never generates. `GET /docs` serves a Swagger UI shell pointed at that document. The mounts are stage [4c] of `src/httpapi/app.ts` — after the routes they document, before the UI namespace — so a documented route always exists by the time the document can be requested. Nothing else mounts under `/docs`: an unknown `/docs/*` path falls through to the app's envelope 404 like any unmatched route.
2. **Generated from code, not handwritten; descriptive, not validating; build-time, not runtime.** `src/httpapi/openapi.ts` carries the zod wire schemas, the `describeRoute` operation configs for all eleven routes, the document options, and the `OPENAPI_ROUTES` table (key, method, path per route); the build script mounts stub routes from that table and compiles the document — **no handler executes during generation**, so generation can never fire a discovery POST or touch an upstream. The runtime never imports the description module: `app.ts` mounts plain handlers and serves the generated artifact, so `hono-openapi` and `zod` are devDependencies, not runtime dependencies. The gateway adds no `validator()` middleware — the specs remain the only normative wire contract; the zod layer mirrors them.
3. **Ungated, declared per the SECURITY.md surface rule (hard constraint 10).** The two new routes belong to the `/docs` documentation surface and are deliberately covered by no gate: the auth stage passes the namespace through untouched because it matches no gate prefix (`/api/*` session gate, `/llm/v1/*` Bearer gate). The rationale: the surface serves static protocol metadata — route paths, request/response shapes, the fixed mask literals — and zero instance data: no credential, no configuration value, no probe outcome, no alias, no payload. It is the same trust class as `/ui/*` under [ADR-005](./005-gateway-surface-namespace.md), and SECURITY.md's attack surface lists both routes.
4. **CDN assets, pinned.** The shell is an HTML constant (`SWAGGER_UI_HTML`, `src/httpapi/docs-shell.ts` — the one docs module the runtime imports, dependency-free by design); the *document* is the build artifact, the shell is not. Its stylesheet and bundle are pinned to `swagger-ui-dist@5.35.0` and loaded from unpkg **in the operator's browser**; the gateway itself never fetches anything, and the page carries no data beyond the document URL. Pinning the exact version is the load-bearing determinism control: an unpinned upstream UI release would silently change this gateway surface.
5. **The specs stay authoritative; the document is a projection.** Every schema in `src/httpapi/openapi.ts` cites the contract it mirrors, and where prose and document could disagree, the specs win and the module is corrected in the same change (SECURITY.md hard constraint 12). The document describes the *interface*, not a deployment: all eleven operations appear unconditionally, and the auth actions' own descriptions state the `auth.enabled` condition — a static artifact cannot track per-deployment mounts, and a stable description is what SDK consumers need. A three-way sync test asserts document ≡ `OPENAPI_ROUTES` ≡ the mounted route table (in the full-credential fixture), so the projection cannot silently lose or gain an operation against either the table or the server.

## Consequences

Positive:

- Integrators, SDK codegen, and browsable-reference readers are served by a stable, deployment-independent document: the same eleven operations in every deployment, with the conditional auth actions documented as conditional.
- Zero runtime cost and zero behavior change: serving is a file read, and the runtime tree carries none of the description machinery — `hono-openapi` and `zod` are devDependencies, with no security-critical function delegated to them at runtime (SECURITY.md, Dependency Management).
- No asset pipeline and no vendored bundle: the shell is one constant, and the served-document surface stays one JSON response.

Negative:

- A CDN dependency at the *browser* edge: an air-gapped LAN browser cannot render the UI shell (unpkg unreachable). The JSON document still serves — any OpenAPI viewer can be pointed at `/docs/openapi.json` directly.
- The document is a de-facto client surface: its shapes are the zod mirrors of the contracts, so reshaping a wire field or an operation is a breaking-change item that updates the contract *and* `src/httpapi/openapi.ts` in the same change — both contracts' checklists now say so.
- A second description of the wire exists and can drift from the prose specs. Mitigations: the specs-are-authoritative rule above, the sync test pinning the operation set, and the contracts' breaking-change checklists naming the module.
- A build artifact exists and must be kept fresh: an API change without a follow-up `bun run apidocs` leaves the served document stale. Mitigations: the freshness test compares the artifact against a fresh generation (and bootstraps it on a fresh checkout), the sync test pins the operation set, the contracts' breaking-change checklists name both the module and the script — and until the artifact is generated the docs route answers the envelope 404 with the regenerate hint, visible rather than silent.

## Alternatives Considered

- **Handwritten OpenAPI document plus a sync test:** rejected — two artifacts describing one route table invites exactly the drift the sync test would then chase; a `describeRoute` config is attached to the mount itself, so removing a route mechanically removes its description.
- **A documentation section inside the SPA (`/ui`):** rejected — it couples documentation to the SPA build and its session-gated data surface, and hides machine readability behind a React app; SDK consumers need the raw document at a stable URL, not a client-rendered view.
- **JSON-only (no Swagger UI page):** rejected — human discoverability was a primary goal, and the shell costs one data-free HTML constant; the UI's trust profile stays at the `/ui` level precisely because it carries nothing but the document URL and pinned assets.
- **Vendored `swagger-ui-dist`:** rejected — it vendors a large third-party bundle into the repository and duplicates the supply-chain surface that a pinned CDN URL already narrows; the pin keeps the browser-served bytes deterministic without repo bloat.
- **Unpinned CDN assets (`swagger-ui-dist@latest`):** rejected — an upstream UI release would change this gateway's surface silently; the exact-version pin is the whole point of using a CDN.
- **Generate the document at request time (runtime introspection):** rejected — it kept `hono-openapi` and `zod` in the runtime tree for work the build can do once, made the document instance-dependent (the auth actions appearing and disappearing per deployment), and added a generation-plus-memoization path to the serving app; a static artifact keeps the runtime dumb and the description stable, and the three-way sync test keeps the artifact honest against the code.
